Website Change Monitoring API: Detect Page Changes with a Webhook

snapwatch | Sep 2026 | 7 min read

Engineers building competitor intelligence tools, compliance automation, or content aggregators all share the same underlying problem: you need to know when a web page changes. The traditional answer is a cron job that polls the URL, fetches the HTML, hashes it, compares against a stored value, and fires a notification. The modern answer is a webhook-first API that does all of that for you — in a single POST request.

This guide walks through both approaches so you can see exactly what you are replacing, then shows how to wire up snapwatch to start receiving change webhooks in minutes.

The polling problem: ~80 lines you do not need to write

The DIY path looks simple at first. Fetch a URL, hash the content, compare. But by the time you handle errors, retries, storage, deduplication, and notification delivery, you have a small service to maintain. Here is what that typically looks like:

Node.js DIY approach — the code you skip 
// package deps: node-cron, node-fetch, crypto, nodemailer (or Slack SDK)
import cron from 'node-cron';
import fetch from 'node-fetch';
import crypto from 'node:crypto';
import fs from 'node:fs';

const WATCH_URL = 'https://example.com/pricing';
const HASH_FILE = './last-hash.txt';
const WEBHOOK  = process.env.NOTIFY_WEBHOOK;

function hash(str) {
  return crypto.createHash('sha256').update(str).digest('hex');
}

async function checkPage() {
  try {
    const res  = await fetch(WATCH_URL, { timeout: 10000 });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const body = await res.text();
    const current = hash(body);

    let previous = '';
    if (fs.existsSync(HASH_FILE)) {
      previous = fs.readFileSync(HASH_FILE, 'utf8').trim();
    }

    if (current !== previous) {
      fs.writeFileSync(HASH_FILE, current);
      await notify(WATCH_URL, previous, current);
    }
  } catch (err) {
    console.error('Poll failed:', err.message);
    // TODO: retry logic, dead-letter queue, alerting on repeated failure
  }
}

async function notify(url, oldHash, newHash) {
  await fetch(WEBHOOK, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      message: `Page changed: ${url}`,
      old_hash: oldHash,
      new_hash: newHash,
      // no diff, no screenshot, no content summary
    }),
  });
}

// Run every 15 minutes — but this needs to stay alive 24/7
cron.schedule('*/15 * * * *', checkPage);
console.log('Watcher running...');

This works until it does not. The process needs to stay alive. You need persistent storage for hashes. You get no diff of what changed, no screenshot, no retry budget, and no way to manage multiple watched URLs without turning this into a proper application. That is the polling trap.

⚠

Hash comparison only tells you something changed. It tells you nothing about what changed — a single cookie banner update looks identical to a price change in your diff logic.

The API approach: one JSON object, one webhook

A website change monitoring API inverts the model. Instead of you polling and storing state, you register a watch once, and the API calls you when something changes. The infrastructure — distributed polling, deduplication, diff extraction, screenshot capture — lives on the API side.

The key properties of a good change monitoring API:

  • Webhook-first — push, not pull. No polling loop in your codebase.
  • Structured diffs — know what changed, not just that it changed.
  • Screenshots on change — visual confirmation alongside the diff.
  • Configurable intervals — check every minute or every day, your choice.
  • Managed retries — the API handles transient failures, not your code.

Setting up a watch with the snapwatch API

Registering a watch is a single POST to /watches. You provide the URL to monitor, the webhook endpoint to notify, and how often to check.

curl

bash Register a watch 
curl -X POST https://api.snapwatch.dev/watches \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://competitor.com/pricing",
    "webhook_url": "https://yourapp.com/webhooks/snapwatch",
    "check_interval_minutes": 60,
    "label": "Competitor pricing page"
  }'

The API responds with a watch_id you can use to pause, update, or delete the watch later. That is all the setup required.

Node.js

JavaScript Full example — register + handle webhook 
// 1. Register the watch (run once, e.g. in a setup script)
const res = await fetch('https://api.snapwatch.dev/watches', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${process.env.SNAPWATCH_API_KEY}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    url:                    'https://competitor.com/pricing',
    webhook_url:            'https://yourapp.com/webhooks/snapwatch',
    check_interval_minutes: 60,
    label:                  'Competitor pricing page',
  }),
});

const { watch_id } = await res.json();
console.log('Watch created:', watch_id);

// 2. Handle the inbound webhook (Express / Hono / whatever)
app.post('/webhooks/snapwatch', async (req, res) => {
  const event = req.body;

  if (event.event_type === 'changed') {
    await notifyTeam({
      url:        event.url,
      summary:    event.diff_summary,
      screenshot: event.screenshot_url,
    });
  }

  res.sendStatus(200);
});

The webhook payload you receive

When snapwatch detects a change, it delivers a signed POST to your webhook_url. The payload includes a structured diff summary and a URL to the before/after screenshots:

JSON Inbound webhook payload 
{
  "event_type":     "changed",
  "watch_id":       "wch_01j9z3k4m5n6p7q8",
  "label":          "Competitor pricing page",
  "url":            "https://competitor.com/pricing",
  "checked_at":     "2026-09-04T14:22:31Z",
  "diff_summary": {
    "added_text":   ["New: Enterprise plan at $299/mo"],
    "removed_text": ["Business plan at $199/mo"],
    "change_score": 0.12,
    "sections_changed": ["pricing-table", "faq"]
  },
  "screenshot_url":  "https://cdn.snapwatch.dev/screenshots/wch_01j9z.before-after.png",
  "before_snapshot": "https://cdn.snapwatch.dev/snapshots/wch_01j9z.2026-09-03.html.gz",
  "after_snapshot":  "https://cdn.snapwatch.dev/snapshots/wch_01j9z.2026-09-04.html.gz"
}
ⓘ

Every webhook is signed with an X-Snapwatch-Signature HMAC header so you can verify the payload came from snapwatch and was not tampered with.
