Common questions

FAQ

Does snapwatch handle pages behind login or bot protection?

No — snapwatch monitors publicly accessible pages. If a page returns a CAPTCHA or access-denied response, we fire a blocked event so your system knows the check ran but was blocked. We won't silently fail. Most SaaS pricing, changelog, and docs pages are public and work reliably.

How is this different from changedetection.io?

changedetection.io is a self-hosted dashboard. snapwatch is a REST API. If you're building a product (a competitor tracker, price monitor, compliance tool), you want an API you can call programmatically — not a Docker container you maintain. snapwatch fits inside your architecture; changedetection.io is your architecture.

What happens when nothing changes?

Every Monday at 9am UTC, your webhook receives a weekly_digest event with a count of checks run and changes found. Quiet monitors still deliver value — you know they're running cleanly. This prevents the "I forgot I was paying for this" churn pattern.

Where do the screenshot diffs come from?

We use our own shot.dev infrastructure — the same Cloudflare Browser Rendering API that powers shot.dev. Before/after screenshots are stored on Cloudflare R2 and linked in every changed webhook. No third-party screenshot service, no additional latency.

Can I monitor a specific section of a page?

Yes — pass a css_selector when creating a watch. We record the selector and use it to scope the diff. Example: #pricing-table to monitor only the pricing section and ignore navigation, footer, and cookie banners.

What's the check frequency on each plan?

Starter: 1-hour minimum. Pro: 15-minute minimum. Scale: 5-minute minimum. You set check_interval_minutes on each watch — it can be longer than the plan minimum but not shorter. Most use cases (competitor monitoring, compliance tracking) work well at 1-hour frequency.
